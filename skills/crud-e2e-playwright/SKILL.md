# Browser tests with Playwright

## What it gives you

- `frontend/playwright.config.ts`: Chromium, 1 worker, traces + screenshots on failure. The config starts the Go API
  itself (`go run ./cmd/server` on port **8090**) serving the **built** SPA, against the **`app_e2e`** database, so the
  tests don't touch your dev data and can run while `task dev` is running.
- `frontend/e2e/`:
  - `auth.setup.ts`: the first signup on the fresh database becomes admin; its session is saved for admin tests.
  - `auth.spec.ts`: login redirect, signup/sign-out/sign-in, wrong password, admin-only Users page.
  - `teams.spec.ts`: team admin adds a member; the member can view but not manage; deleting the team hides it.
  - `<resource>.spec.ts`: one per resource, generated by `add-resource.sh`: create → hidden from another user →
    share as viewer → read-only for them → edit → delete → access gone.
  - `helpers.ts`: `newUser` (separate browser context = separate user), `signup`, `share`, `grant`.
- Tasks: `task e2e` (reset `app_e2e`, build, run), `task e2e:ui`, `task e2e:report`, `task e2e:install`.
  `task check` also runs `e2e`.

## Install

New apps get it from `new-app.sh`. For an existing crud-* app (safe to re-run):

```bash
<skills-dir>/crud-e2e-playwright/scripts/add-e2e.sh <app-dir>
```

It adds `@playwright/test`, downloads Chromium, copies the config and specs (never overwrites existing specs),
generates specs for resources that already exist, adds the Taskfile tasks and ignore rules, then type-checks and lints.

## Run

```bash
task e2e                      # headless, all specs
task e2e -- --headed          # watch the browser
task e2e -- e2e/clusters.spec.ts -g "shares"   # one file / test name
task e2e:ui                   # interactive UI mode with time-travel
task e2e:report               # open the HTML report after a failure (trace viewer)
```

Needs Docker (Postgres from `docker-compose.yml`) and, once per machine, `task e2e:install`.
Port 8090 must be free (override with `E2E_PORT`).

## Writing tests

- **One user per browser context.** Use `newUser(browser, baseURL, "Name")` for every person in a scenario. The
  default `page` fixture is the admin, who bypasses all permission checks, so don't use it to test ReBAC.
- **Use roles and labels**, as the UI renders them: `getByRole("button", { name: "New cluster" })`,
  `getByLabel("Name", { exact: true })`, `getByRole("link", { name })`. Avoid CSS selectors and `nth()`.
- **Make data unique** (`` `Cluster ${Date.now()}` ``, `uniqueEmail`) so tests are independent of order.
- **Assert permissions both ways**: what the user can see *and* that forbidden buttons are hidden *and* that the
  direct URL shows `do not have view access`.
- Never use `waitForTimeout`; rely on `expect(...).toBeVisible()` auto-waiting.
- Radix `Select`: click `getByRole("combobox")`, then `page.getByRole("option", { name })`. Options render in a portal,
  so look them up on `page`, not inside the dialog.

## When you change a resource

After adding required fields in `crud-resource` step 3, update `frontend/e2e/<resource>.spec.ts`: fill the new
inputs in the create step (and edit step if needed), and assert one important field on the detail page.
For a **child** resource, create the parent first in the spec and open the child list from the parent detail page.

## Debugging failures

1. `task e2e:report`: open the failed test and look at the trace (DOM snapshots, network, console).
2. `task e2e -- --headed --debug -g "<test name>"` to step through.
3. `first signup must be admin`: the database wasn't fresh; always run through `task e2e`, not bare `playwright test`.
4. `webServer timed out`: the Go server didn't start; run `cd backend && go build ./...` and check that the
   database is up (`task db:up`).
5. A locator matches 2 elements (strict mode): make it more specific (`exact: true`, or scope to `getByRole("dialog")`).
